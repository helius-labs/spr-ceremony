    What am I trusting?
    
The worker uses the browser’s cryptographic random source, checks the input hash, computes the contribution, and verifies it locally. Only the public result is uploaded. The coordinator independently verifies it and commits a checkpoint before accepting it.

    
You are trusting the code delivered by this host and your computer. A compromised host or extension could steal randomness. For an independently checked build, use the native client or review and host the source yourself. Neither browser nor native execution guarantees memory erasure.

    
Public download chunks, completed outputs awaiting acceptance, and receipts are kept in browser storage. Storage can be evicted; save your receipts. A receipt proves inclusion in the checkpoint you checked. Final transcript verification is a separate step.

    
Pausing stops the worker and releases the reservation. A saved output can be reused only while its parent remains the current circuit head. Otherwise a new contribution is required.
